Request Execution Lifecycle

Every incoming prompt executes sequentially through the four team pillars. The goal is to maximize cost reduction while enforcing strict latency and quality bounds.

Step 1 — Phase 1 Member 1

Layered Caching

Exact-match → semantic with NER verifier → provider prompt caching.

Latency: < 5 ms lookup
Precision: 0% false hits
Step 2 — Phase 2 Member 2

Routing & Decisions

RouteLLM CPU baseline or System-1 classifier with rate-limit fallbacks.

Decision: < 15 ms
Allocation: SLM vs Frontier
Step 3 — Phase 3 Member 3

Context Optimization

Lossless Headroom pruning followed by entropy token reduction.

Pruning: 3×–5× compression
Retention: > 95% reasoning
Step 4 — Phase 4 Member 4

Eval & Telemetry

DeepEval scoring, OpenTelemetry traces, transparency receipts.

Metric: Quality / $ saved
Output: Headers & sidecar

Cross-Phase Dependencies

Each phase depends on outputs from the others. These dependencies are explicit so the team can plan handoffs and avoid duplicated work.

Baseline definition

Owned jointly by all four members. Must be frozen before any policy is measured. "Always use the strongest model" is the denominator for all savings calculations.

Transparency Receipt schema

Touches all four phases. Member 4 leads, but all contribute fields. Includes normal cost, chosen optimization, final cost, quality retained, and net savings.

Candidate model pool

Defined by Member 2, but shared with Member 1 (cache key) and Member 3 (compression threshold per model). Changes require re-embedding for CLM.

False-hit test suite

Built by Member 4 but used daily by Member 1. Curated tricky pairs: entity swaps, negation, time-sensitive queries. Run before every semantic-cache change.

Public data strategy

Owned by Member 4 but informs Member 3's quality regression suite. Synthetic and public datasets reduce dependence on real Metis data per the confidentiality brief.

Compression ↔ Routing latency

Member 3's compression threshold must align with Member 2's routing latency budget. Compression adds pre-processing latency before the router runs.

Weekly Rhythm & Deliverables

A lightweight cadence keeps the team aligned without adding overhead.

Weekly R&D update

Each member gives a 15-minute update: one paper, one tool, one open question. Cross-phase dependencies are surfaced early.

Decisions log

Every build/skip decision is captured with justification. The log becomes the backbone of the final report.

Per-member R&D report

4–6 pages covering literature, tools, techniques, open questions, and a concrete recommendation. Plus a prototype or demo if feasible.

Integrated architecture doc

The team jointly produces a single document mapping the four phases onto the request lifecycle and identifying the minimum viable implementation.
